PHP2Shell: two PHP bugs and a Linux root bug

CVE-2026-109618 · CVE-2026-109619 · CVE-2026-46300

In plain English

PHP runs a huge share of the web. Two bugs in PHP let an attacker take over a web server. One crafted request is enough. No password is needed. A third bug, in the Linux kernel, turns that foothold into full "root" control, says CISA.

What is happening now

  • watchTowr saw attack attempts on 21 Oct, the day the fixes shipped.
  • CISA added both PHP bugs to KEV on 26 Oct. The deadline was 29 Oct. It added the kernel bug on 28 Oct. That deadline is today.
  • CISA says the kernel bug "can be chained with" both PHP bugs "to implant PHP webshells and run commands as root".
  • Some firms took sites offline as a precaution, including BambooHR and Dutch government sites (press reports).

Technical detail

  • Both PHP bugs score CVSS v4.0 9.2 (set by the PHP project). Their exploit-likelihood score (EPSS) is 99.999%. Fixed in PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35.
  • Affected versions go back to 5.4. PHP 8.1 and older get no official release. Source backports exist for 7.4, 8.0 and 8.1. Distros may backport under the old version number, so check your vendor's notice. PHP 8.2 reaches end of life on 31 Dec 2026.
  • Highest risk: Apache mod_php. One unauthenticated request is handled before your app code runs. PHP-FPM, php-cgi, FrankenPHP and LiteSpeed are also at risk.
  • A separate path leaks worker memory, such as passwords, tokens and API keys, without running any code.
  • Kernel bug CVE-2026-46300 scores CVSS 3.1 7.8 (local access, low privileges). "Local" means the attacker must already run code on the box. A PHP webshell gives them exactly that. EPSS is 16.1%.
  • Fixed kernels: 5.10.257, 5.15.208, 6.1.174, 6.6.141, 6.12.91, 6.18.33, 7.0.10 and 7.1. Red Hat has fixes for RHEL 8, 9 and 10. It says RHEL 6 and 7 are not affected.

What to do

  1. List every host that runs PHP: web servers, containers, CMS and legacy apps.
  2. Patch PHP to a fixed version. Updating WordPress or Laravel does not update PHP itself. Restart Apache, PHP-FPM or workers afterwards.
  3. Patch the Linux kernel on the same hosts. This needs a reboot.
  4. Cannot patch today? The PHP project lists partial settings. For CVE-2026-109618: memory_limit=-1 and a low post_max_size. For CVE-2026-109619: session.upload_progress.enabled=0, and on PHP 8.5 also fatal_error_backtraces=0. These reduce risk. They do not fix it. A WAF helps, but Cloudflare reports attackers changing payloads to dodge WAF rules.
  5. Hunt for signs of attack: new .php files in web roots, web server processes starting shells or curl and wget, and unexplained worker restarts or spikes of HTTP 500 errors.

GitLab: a CI regular expression leads to remote code execution

CVE-2026-97229 · also CVE-2026-110264

In plain English

GitLab holds your source code, build pipelines and secrets. This bug lets an attacker run commands on the GitLab server itself. It starts with a text-matching pattern (a "regular expression") that GitLab builds from attacker-supplied input. A crafted pattern corrupts memory. The attacker then takes over.

What is happening now

  • CISA added it to KEV on 29 Oct, 17 days after the fix. The deadline is 1 Nov.
  • GitLab scores it 10.0 with no privileges needed. GitLab.com and GitLab Dedicated are already patched. Self-managed installs must upgrade.
  • Public exploit code exists. A Metasploit module sits in an open pull request. It first needs an account that can push to a public project. Then one request, with no login, triggers the bug and runs a command as the GitLab git account.
  • A second critical bug, CVE-2026-110264 (CVSS 10.0), was fixed on 21 Oct. It is in the same regex engine. It was not on KEV in catalog 2026.10.29.

Technical detail

  • CVE-2026-97229 is an integer overflow (CWE-190). It happens when GitLab compiles a regular expression taken from a CI/CD configuration. GitLab's score: CVSS 3.1 10.0 (AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H). EPSS is 26.6%.
  • Affected: 19.2 before 19.2.8, 19.3 before 19.3.5, and 19.4 before 19.4.2 (CE and EE).
  • The root cause is a bug in Ruby's regex engine (Onigmo). Ruby fixed it in 4.0.8, 3.4.12 and 3.3.13. Ruby advises 4.0.9, 3.4.12 or 3.3.13 or later.
  • Other software may be affected. Any app that builds a regex from attacker-controlled text can be: Regexp.new, Regexp.union, Regexp.compile or /#{input}/. Regexp.timeout does not protect. Ruby requested no CVEs of its own, so scanners may show only GitLab's IDs.
  • CVE-2026-110264 affects every GitLab version from 7.0 up to the 21 Oct releases. GitLab says no login is needed. Fixed in 19.5.1, 19.4.3, 19.3.6, 19.2.9, 19.1.9, 19.0.10 and 18.11.13.
  • GitLab published six detections for self-managed instances. Examples: regex-engine worker crashes and bursts of CI lint errors.

What to do

  1. Find every self-managed GitLab, including old and forgotten ones. The version shows on the /help page.
  2. Upgrade to the 21 Oct patch release or later: 19.5.1, 19.4.3, 19.3.6, 19.2.9, 19.1.9, 19.0.10 or 18.11.13. This fixes both bugs. Plan for downtime on single-node installs, because GitLab says the patch includes database migrations.
  3. If you run your own Ruby (source installs), update Ruby too.
  4. Stop-gap until you patch (general hardening, not a GitLab fix): limit network access to GitLab and turn off open sign-up.
  5. Hunt: use GitLab's published detections. Look for shells or unexpected child processes under the git account.

Cisco ASA and FTD: one crafted VPN request reboots the firewall

CVE-2026-76418 · Cisco bug CSCwx26625

In plain English

Many firms use a Cisco firewall to give staff VPN access. This bug lets anyone on the internet send one crafted request to the VPN service. The firewall then reloads. Staff lose VPN while it restarts. Cisco says attackers are already using it.

What is happening now

  • Cisco's advisory (28 Oct) says its PSIRT "became aware of active exploitation" in October 2026.
  • CISA added it to KEV on 29 Oct. The deadline is 1 Nov.
  • The EPSS score is only 0.9%. Ignore it here. Cisco and CISA both confirm real attacks.

Technical detail

  • The bug is a logic error in the Remote Access SSL VPN service. It appears when secondary authentication is set on a tunnel group (CWE-690). A crafted request makes the device reload. That is a denial of service. CVSS 3.1 8.6 (AV:N/AC:L/PR:N/UI:N/S:C/C:N/I:N/A:H).
  • No VPN login is needed to reach the bad code path.
  • You are exposed only if all three are true: you run a vulnerable release; SSL VPN is reachable (webvpn with enable <interface>); and secondary authentication is set on a tunnel group.
  • Check secondary-authentication-server-group in every tunnel group. Include DefaultWEBVPNGroup, even if tunnel-group-list is off.
  • Not affected: Cisco's cloud-delivered Firewall (CDFW), cdFMC, Secure Access and Secure FMC.
  • First fixed ASA releases: 9.16.4.104 (9.16 and earlier), 9.18.4.96, 9.20.4.50, 9.22.3.200, 9.23.1.48, and 9.24.1.27 or 9.24.10.1. First fixed FTD releases: 7.0.11 (7.0 and earlier), 7.2.13, 7.4.9, 7.6.7, 7.7.14, 10.0.3 and 10.1.1.

What to do

  1. Check all three conditions on every ASA and FTD you run. Include branch offices and devices managed by partners.
  2. If you are exposed, upgrade to the first fixed release for your train.
  3. Cisco lists no workaround. The stop-gap is to switch off secondary authentication on the affected tunnel groups. Cisco's advisory gives the exact commands. This removes a login step, so it lowers VPN security. Use it only until you patch.
  4. Check device logs for unexplained reloads.

Brotli: a compression library bug that can run code

CVE-2026-111497

In plain English

Brotli shrinks web content. Many programs use it to unpack data they receive. A bug in the unpacking code lets a crafted file overwrite memory. In the worst case, the attacker runs code. You are at risk only if your app unpacks Brotli data that an attacker can send.

What is happening now

  • CISA added it to KEV on 27 Oct. The deadline is 10 Nov.
  • Imperva showed code execution on an unmodified Node.js 24.22.0 (Linux ARM64). It did not release the exploit.
  • The Hacker News said on 24 Oct that no attacks in the wild had been reported. An earlier CISA assessment (23 Oct) also recorded none. CISA then listed it on 27 Oct. The listing is the later, stronger signal.
  • EPSS is 82.6%. That is high.

Technical detail

  • Cause: an unchecked return value in the decoder (CWE-252). It leads to an out-of-bounds memory write (CWE-787). A crafted stream can corrupt memory, leak memory, crash the app, and maybe run code.
  • CVSS v4 9.2 (Google, the CVE assigner). CVSS v3 9.8 (via Shodan CVEDB). Others score it lower: Red Hat and Microsoft use 8.1 (per The Hacker News). Node.js rates it high.
  • Affected: Brotli 1.0.3 to 1.2.0. Fixed in 1.0.10, 1.1.1 and 1.2.1.
  • Reported as affected: Node.js, Bun, .NET, Python (Brotli and brotlicffi), Envoy, Istio, ClickHouse, Apache Arrow, FFmpeg and libjxl, and cdxgen.
  • Fixed runtimes: Node.js 22.23.4, 24.22.1 and 26.12.1. Bun 1.4.4. .NET 8.0.33, 9.0.22 and 10.0.14 (Microsoft shipped out of band on 25 Oct). Python Brotli 1.2.1 and brotlicffi 1.2.1.0.
  • You are exposed only if your app decodes Brotli data an attacker controls. Examples: fetch() of a response with Content-Encoding: br, or Express and body-parser handling br request bodies.

What to do

  1. List the apps that decode Brotli: Node.js, Bun, .NET and Python services, proxies, and anything that bundles its own copy.
  2. Update the runtime or library to a fixed version. Rebuild and restart containers. Updating a base image alone may not reach bundled copies.
  3. Cannot update yet? Reject Content-Encoding: br at the edge. Turn off automatic Brotli decoding. Remove the Python Brotli packages if you do not use them.
  4. Check your software inventory or scanner for Brotli, Node.js and .NET versions.

  • If you use Vulnerability Management, it can list vulnerable applications the agent sees installed, such as Node.js and .NET runtimes.

Fake Claude Code extension in the Cursor marketplace

No CVE · versions 2.1.312 and 2.1.313 of "Anthropic.claude-code"

In plain English

On 29 Oct, a fake Claude Code extension sat in Cursor's marketplace for about 11 hours. Anyone who installed it got a hidden remote-access key and a job that comes back after a restart. Cursor says Anthropic did not make it. Cursor reportedly says at most 5,000 users were affected. Removing the extension is not enough.

What is happening now

  • Cursor posted a notice on 29 Oct and updated it on 30 Oct. Bad versions: 2.1.312 and 2.1.313, for Windows and macOS. Live from about 02:27 to 13:35 PT on 29 Oct.
  • Cursor removed the version, shut the marketplace, rotated keys and rebuilt. The attacker's server was taken offline.
  • The Hacker News (30 Oct) quotes Cursor's "at most 5,000 users" figure. It says it is not known on Open VSX or the Microsoft VS Code Marketplace. How the attackers got in is still unclear.

Technical detail

  • A short loader (66 lines, per OpenSourceMalware) runs before the real extension code. It collects hostname, username, OS, architecture, home directory, environment variable names, working directories, git email and public IP.
  • It adds an attacker SSH key to authorized_keys (key comment svc-telemetry). It tries to turn on SSH and open a reverse SSH tunnel to the attacker. That needs admin rights and fails on most hosts. The key, the persistence and the beacon still happen.
  • Persistence: macOS LaunchAgent com.apple.sysmond. Windows scheduled task SysMon plus a Startup fallback. A Linux cron @reboot entry also appears in the code. The tunnel is retried about every 60 seconds.
  • Indicators (defanged): 134[.]209[.]82[.]225 (reverse SSH on port 22; beacon to port 8099 at /beacon). Key fingerprint SHA256:0Z6R+DF64Do2nwQic8a7kkfDLNNk4IiK+2U2Rci4htk. Files ~/.config/.smt, ~/.config/.smtk and /tmp/.stk_<10 hex>. Payload extension.js SHA-256 ecb58cb29078d9646ad1dcdbe51526f2d9cfea06be5fb2ab183e8ecc3ab6bf15.
  • Lookups to ipify or ifconfig.me alone are not indicators.

What to do

  1. Ask developers: did you install or update Claude Code in Cursor on 29 Oct? Check the extension version.
  2. Run Cursor's check commands and its clean-up scripts (remediate-macos.sh or remediate-windows.ps1). Uninstalling the extension is not enough.
  3. Search endpoint, DNS and proxy logs for the indicators above. Remove any unknown SSH key from authorized_keys, such as one commented svc-telemetry.
  4. If a machine was hit, rotate the credentials used on it: SSH keys, API keys, cloud and git tokens.
  5. Longer term: allow-list extensions and pin versions on developer machines.

WatchAPJ: India

eMudhra certificate authority: 8 compromised CA keys

  • An Indian certificate authority made 8 intermediate CA keys with too little randomness. Anyone can compute the private keys from the public certificates. eMudhra blames a flaw in a key ceremony on 30 Apr 2025.
  • eMudhra says only one of the eight was in use and none issued end-user certificates. It says its own systems were not breached.
  • Chrome and Firefox blocked the certificates within hours of the 17 Oct report. Chrome planned to remove the root on 27 Oct (PT). I did not verify that it happened.
  • CERT-In said on 21 Oct that it had seen no confirmed malicious use.
  • Fixes shipped in Go (1.27.3, 1.26.10), Node.js (26.12.1, 24.22.1, 22.23.4), Firefox 158.0.1, certifi 2026.10.19, Ubuntu and Debian. WordPress 7.1.4 also updated its bundled root certificates. Red Hat posted a workaround (RHSB-2026-012).
  • Side effect: removing a root can break legitimate certificates. Test before you roll out.

What to do: update browsers, runtimes and trust stores. Check whether any of your certificates chain to an eMudhra emSign root. S1 angle: none direct. This is a certificate and trust-store problem.

ARTEX: an AI-driven intrusion toolkit used at scale (Vapor Panda)

  • CrowdStrike (29 Oct): from 17 Oct, one ARTEX controller was used against 200+ organisations in at least 14 countries over 11 days. Targets include foreign ministries, a Middle East interior ministry, 19 US organisations, and telecoms in the US, Belgium and the Philippines.
  • The group, Vapor Panda, has targeted Oceania among other regions since 2021. CrowdStrike confirmed hands-on activity at 9 organisations and password spraying against at least 12 more.
  • A human operator steers the AI agents. In one case the operator told them to find Windows hosts without the CrowdStrike Falcon sensor. Expect attackers to hunt for any endpoint that lacks protection.
  • CrowdStrike's advice: rotate keys and credentials, enforce SAML signature validation, require IMDSv2, restrict cloud roles that can run commands, patch edge appliances, and run EDR everywhere, including internal servers.
  • Hunt for ARTEX markers: artx or artex in command lines, artx-prefixed cloud roles, art18- comments, and C:\ProgramData\artx5v\.
  • Indicators (defanged): nginxmysql[.]com (45.153.126[.]223), sqlserver-sqlite[.]com (89.46.234[.]50), www[.]ddduuuppp[.]com (192.121.47[.]20).

S1 angle (capability-based): S1 has not published an ARTEX-specific protection statement. Its Week 43 roundup only reports on the campaign. In general, the agent watches process, file and network behaviour on endpoints and servers. Web shells, DLL side-loading and credential theft, which are techniques in CrowdStrike's list, are the kind of behaviour it is built to flag. It does not manage your SAML, IMDS or cloud role settings. Those are cloud configuration jobs. One lesson from the report: attackers look for hosts with no agent, so check your agent coverage.
